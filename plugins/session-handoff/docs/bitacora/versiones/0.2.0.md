# 0.2.0 — Los hashes que faltan se recuerdan hasta que estén

- **Fecha**: 2026-11-19 · **Commit**: `0c9c45a` · **Tipo**: feat
- **Visto en**: lote de specs

## Síntoma

Una interrupción (el reporte de un cron) justo después del recordatorio de un commit hizo que el hash nunca llegara
a `PROGRESS.md`: el aviso salía una sola vez.

## Cambio

- El plugin guarda los hashes de la sesión que `PROGRESS.md` no cita y los recuerda en cada commit, en cada mensaje
  nuevo (`UserPromptSubmit`) y al terminar el turno (`Stop`, evento `stop.commits`). Se limpian al escribir
  `PROGRESS.md` con ellos.
- Con `git commit -q`, el hash sale de `git log -1` en el repo del `cd` o de `git -C`, también con rutas de Git
  Bash como `/d/...`.

## Prueba

`a hash left out survives an interruption: the next prompt and the Stop ask for it` (`hooks/register.test.ts`).

## Lección

Un aviso que sale una sola vez se pierde con la primera interrupción. Ver también [0.4.1](0.4.1.md) y
[0.4.2](0.4.2.md).
