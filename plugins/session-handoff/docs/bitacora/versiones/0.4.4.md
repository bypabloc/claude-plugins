# 0.4.4 — Una línea de estado repetida se nombra al escribir

- **Fecha**: 2026-11-20 · **Commit**: `f2fe629` · **Tipo**: fix
- **Visto en**: content-studio, lote 001–023 (spec 011, grupo 4)

## Síntoma

`stop.block` 1, 2, 3 y otra vez 1, 2, 3 hasta `reason: cap` en tres minutos, con la sesión convencida de estar en
`external-wait`: cada aviso de `Stop` citaba un `Next step` que ella ya daba por resuelto.

## Causa

La sesión escribió `Phase: external-wait — …` en una línea nueva, más abajo y justo antes de `## Espera`, y dejó
arriba el `Phase: implementation — …` original. `progressFields` toma la primera línea de cada etiqueta, así que
`Stop` veía `implementation` y bloqueaba. La segunda línea se ignoraba sin aviso.

## Cambio

- `duplicateText` en `hooks/handoff.ts`: si `Status:`, `Phase:` o `Next step:` aparecen más de una vez, el
  `PostToolUse` de `PROGRESS.md` lo dice y nombra cuál cuenta.
- `Done:` puede repetirse (hay proyectos que lo usan en varias líneas) y no se avisa.

## Prueba

`a second Phase line is named right away: Stop reads only the first one` (`hooks/register.test.ts`).

## Lección

Lo que `Stop` decide a partir de una línea tiene que ser una sola línea. Si el plugin descarta algo que el agente
escribió, debe avisarlo cuando se escribe (como en [0.3.4](0.3.4.md)).
