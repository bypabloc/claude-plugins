# 0.1.0 — Recordatorio del hash tras cada commit; un lote es un solo handoff

- **Fecha**: 2026-11-19 · **Commit**: `373afd9` · **Tipo**: feat
- **Visto en**: diseño, a partir de las primeras sesiones con lotes de specs

## Cambio

- `PostToolUse` de Bash: tras un `git commit`, si `PROGRESS.md` del trabajo vinculado no cita el hash, pide
  anotarlo en esa misma respuesta (evento `commit.remind`).
- Un lote es un solo trabajo: `Done` suma cada spec, `Next step` pasa a la siguiente y `Status: done` va solo tras
  la última. La fase `closing` vuelve a `implementation` si quedan specs.
- Con `Status: done`, el cierre siempre pide borrar el handoff y sus vínculos, también con un `closing` propio del
  proyecto.

## Prueba

`a git commit in Bash asks for its hash in PROGRESS.md until it is there` (`hooks/register.test.ts`).

## Lección

Sin el hash en `Done`, una sesión que retoma tras compactar no sabe qué parte ya está confirmada y repite trabajo.
